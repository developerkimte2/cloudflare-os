# Sales OS — 2026-09-14 現状検証レポート

観点は 2 つ。**「まったく不慣れな営業担当でも使えて、営業行為だけに集中できるか」** と **「上司が一目で状況を確認できるか」**。
コンサルタント視点で、いま起きている問題・これから起きる問題を洗い出し、優先順位を付けた。実装はしていない（本書は判断材料）。

## 0. 検証の方法と前提

- **実データでの一括テスト**: 営業メモ 31 件 (`capture_test_samples.csv`) を、実際の AI (ローカル Ollama `qwen3-coder:30b`) で `capture()` に通し、結果を全件保存した (`capture_test_results.json`)。
- **コード読解**: `packages/sales-core` (判定ルール・パイプライン)、`packages/gatekeeper-sales/app` (画面)。
- **本セッションで既に直した点**: 未確定の顧客に対する無審査の自動一致 (`2627aaf`)。本書はその**後**の状態を対象にする。
- **注意**: 本番は Workers AI `gpt-oss-120b` の予定 (`plans/deploy-production.md`)。ローカルの 30B モデルより判定品質・速度は上がる見込みだが、**本書で挙げる問題の大半はモデルの賢さではなく設計・画面の問題**なので、モデルを替えても残る。

### 一括テストの数字 (31 件)

| 指標 | 結果 |
|---|---|
| 処理失敗・タイムアウト | 0 件 |
| 人の「確認」が必要になった件数 | 15 / 31 |
| 顧客名が無く「(顧客未特定)」の案件が新規に作られた件数 | **13 件** (毎回別の案件として) |
| 営業関連と判定されたのに次アクションが 0 件だった割合 | **23 / 27** (AI は提案していたが信頼度不足で捨てられた) |
| 期限が曖昧で確認を求めた件数 | 6 件 (うち「来週金曜」の計算が誤り) |
| 営業と無関係と誤判定された件数 | 2 件 (#5 フォロー完了、#23 社内で反対意見) |
| 1 件あたりの処理時間 | 平均 31.6 秒 (22〜47 秒) |

## 1. 結論

骨格は良い。**AI が勝手に確定しない安全弁** (受注・失注・金額・顧客はすべて人が確定)、**取り消し**、**監査ログ**、**プロンプトインジェクション耐性**は、この規模のツールとしてはよくできている。

ただし「誰でも使える」に対しては **入口 (メモを投げる所) に 4 つの壁**がある。

1. **顧客名のないメモがゴミ案件を量産する** — 営業は「来週訪問予定」としか書かない。13/31 がこれ。
2. **AI の失敗が、そのまま「質問」として営業に押し付けられる** — 『「会社名は聞きそびれた」を新規顧客として登録しますか？』
3. **AI の提案が黙って捨てられる** — 23/27 で次アクションが出ない。ツールの一番の売り (今日やることを出す) が働かない。
4. **30 秒待たされる** — 待っている間にもう一度押す、離れる。

「上司が一目で」に対しては、**チーム画面が「案件の一覧」であって「人の状況」ではない**のが最大の欠落。誰が遅れているか、いくら見込めるか、誰が記録していないかが分からない。
そして **入力側 (1〜3) を直さないと、管理画面の数字がゴミ案件で水増しされる**。順番は入口が先。

## 2. 営業担当の視点 — 「誰でも使える・営業に集中できる」か

### A1. 顧客名のないメモが、毎回ゴミ案件になる 【最重要】

- **現象**: 「来週あたり訪問予定。詳細は未定。」→ 顧客「(顧客未特定)」・案件名「来週あたり訪問予定。詳細は未定。」という案件が**新規に**作られる。同様のメモが 13 件 → 13 個の別々の案件。案件一覧がメモの羅列になる。
- **原因**: メモを「どの案件の話か」に紐付ける手段が無い。`CaptureOptions` は `sourceType` と `occurredAt` だけ (`opportunityId` が無い)。取り込み欄は「今日」画面にしか無く、案件・顧客の画面からは投げられない。AI も「直前に見ていた案件」を知らないので、本文に顧客名が無いと必ず新規扱いになる。
- **なぜ困るか**: 現場の営業は電話を切った直後に「来週訪問」とだけ書く。**書き方を教育しないと使えないツールは、「誰でも使える」ではない。**
- **対策**:
  1. 案件詳細・顧客ページに取り込み欄を置き、そこからのメモは**その案件に確定で紐付ける** (`CaptureOptions.opportunityId` を追加し、顧客判定をスキップ)。
  2. 「今日」の取り込み欄でも、顧客名が無いメモは案件を作らず **「どの案件のメモですか？」** と最近触った案件を 3〜5 件ボタンで出す (1 タップ)。「該当なし」なら**メモとして保存** (案件を作らない)。
  3. 「(顧客未特定)」の案件を自動で作る動作は廃止する。
- **効果**: ゴミ案件の根絶、確認の減少、案件一覧・管理画面の数字が信用できるようになる。

### A2. AI の失敗が、そのまま「質問」として営業に出る 【最重要】

- **現象** (実例): 『「会社名は聞きそびれた」は既存顧客に見つかりません。新規顧客として登録しますか？』『「山田太郎様」は既存顧客に見つかりません…』。AI が本文の一節や人名を会社名だと誤認し、その文字列がそのまま質問文になる。
- **なぜ困るか**: 不慣れな人は「はい」を押す。すると **「会社名は聞きそびれた」という顧客**が台帳に生まれる (テストで実際に発生し、無関係な 2 件がその幽霊顧客に統合された。統合の無審査化は `2627aaf` で止めたが、**質問の出方自体**は変わっていない)。
- **対策**:
  1. 顧客に関する質問は、AI が抜き出した文字列を主語にしない。**元のメモを見せて「このメモはどの顧客の話ですか？」** と、①最近の顧客 ②新しい顧客 (名前を入力) ③顧客なし、の 3 択にする。
  2. コード側のガード: 抽出された会社名が文らしい (「は」「を」「。」を含む、「不明」「聞きそびれ」「未定」「わからない」を含む、人名+様) なら**会社名なしとして扱う**。モデルの性能に依存しない決定的な防御。
  3. プロンプトにも明記する (「会社名の手がかりが無ければ空にする」「known accounts の情報を本文の事実として書かない」)。効果は補助的。

### A3. AI の提案が黙って捨てられ、「今日やること」が空のまま 【最重要】

- **現象**: 27 件中 23 件で次アクションが 0 件。決定ログには『0 件の次アクションを作成 (1 件は confidence 不足で保留)』とある。つまり **AI は提案している** (信頼度 0.7〜0.8) が、閾値 0.85 (`nextActionAutoConfidence`) 未満なので `skipped` に入り、**画面のどこにも出ない**。
- **なぜ困るか**: 営業から見ると「メモを書いても何も起きない」。ツールの中核価値が体験できない。
- **対策**: 信頼度不足の提案を **「AI の提案 (未確定)」として取込結果と案件詳細に表示し、1 タップで採用**できるようにする。閾値を下げるより安全で、人が最終判断する設計思想とも一致する。

### A4. 相対日付のたびに質問される。しかも AI の計算が間違う 【重要】

- **現象**: 「来週」「今月中」「来週金曜」がすべて『期限がはっきりしません。AI は〜と読み取りましたが自信がありません』になる (6 件)。「来週金曜」→ AI は 9/21 (月曜) と回答。**正解は 9/25**。
- **なぜ困るか**: 質問が多い上に、提示される既定値が間違っていると、不慣れな人はそのまま確定する。
- **対策**: 日本語の相対日付 (今日/明日/明後日/来週X曜/今月末/来月頭/再来月/N日後) は **コードで基準日から決定的に計算**し、AI の日付より優先する。本当に曖昧なもの (「近いうちに」) だけ質問し、質問するときは日付ボタン (明日/来週/月末/カレンダー) で答えさせる。

### A5. 営業の記録が「無関係」と判定されて消える 【重要】

- **現象**: 「社内で反対意見が出て、話が振り出しに戻ったとのこと」(#23) と「フォローアップ完了。特に進展なし」(#5) が**営業と無関係**と判定され、記録が残らない。#23 は本来「高リスク」のシグナル。
- **なぜ困るか**: 営業が書いたことが黙って消える。後で「言ったのに記録がない」になる。
- **対策**: 「無関係」は雑談・挨拶・テスト入力に限定する。それ以外は、顧客が特定できなくても **A1 の「メモとして保存」** に落とす。判定結果に「やっぱり営業の記録として扱う」の 1 タップを付ける。

### A6. 30 秒待たされる 【重要】

- **現象**: 1 件 22〜47 秒 (ローカル)。画面はボタンが「取り込み中…」になるだけで、その間は待つしかない。本番モデルでも数秒〜十数秒は残る見込み。
- **なぜ困るか**: 不慣れな人は「壊れた」と思い、もう一度押す・画面を閉じる。閉じると結果 (確認の質問) を見ない。
- **対策**: **受付即応答**にする。`receive()` (受付だけして後で処理する API) は既にあるが管理画面から使われていない。取り込み欄は投げた瞬間に「受け付けました。整理中…」と返し、結果は「最近の取込」に届く形にする。処理失敗時の再試行は既にある。

### A7. 確認が溜まる。放置されても誰も気づかない 【中】

- **現象**: 31 件中 15 件が確認待ち。放置すると取込は REVIEW_REQUIRED のまま、顧客は未確定のまま (今回の修正で、未確定の顧客は**次も聞かれる**)。
- **上司へのエスカレーション**は設定値 (`managerEscalationHours: 48`) があるだけで**実装されていない**。
- **対策**: A1〜A5 で質問自体を減らした上で、48 時間放置の確認を上司の画面と朝のブリーフに出す。

### A8. 案件・顧客の整理手段が無い 【中】

- **現象**: 画面から案件や顧客を**削除・統合・アーカイブできない** (できるのは取込の取り消しだけ)。A1 のゴミ案件を片付ける手段が無い。
- **対策**: 案件の統合 (2 つを 1 つに)・アーカイブ、顧客の統合・名前変更を、監査ログ付きで用意する。

### A9. 現場 (スマホ) で使えるか未検証 【要確認】

- 全体が Cloudflare OS の中の iframe で、案件一覧は横 1120px の表。訪問直後に電話から投げられなければ、メモは夜にまとめて書かれ、質が落ちる。**スマホでの取り込み・確認・音声入力を実機で確認する必要がある。**

## 3. 上司の視点 — 「一目で確認できる」か

### B1. チーム画面に「人」の軸が無い 【最重要】

- **現状**: 段階別の件数タイル、停滞・高リスク・契約手続き中の案件リスト、メンバー名簿。
- **無いもの**:
  - **担当者ごとの状況** — 誰が何件持ち、何件期限超過で、いつ最後に記録したか。上司の最初の問い「誰が遅れているか」に答えられない。
  - **金額** — 見込金額の合計・段階別・担当者別・受注予定月別が**どこにも無い**。数字で語れない。
  - **今月の受注・失注**、新規案件数などの推移。
  - **データの健全性** — 未確定顧客の件数、確認待ちの担当者別件数。
- **対策**: チーム画面の先頭に **KPI タイル 1 行** (進行中件数 / 見込金額合計 / 今月受注 / 停滞 / 高リスク / 期限超過アクション / 未確定顧客) と、**担当者別の表 1 つ** (担当 / 進行中 / 見込額 / 期限超過 / 停滞 / 最終記録日 / 確認待ち)。既存のデータだけで作れる。

### B2. 「今日、誰が何をしたか」が見えない 【重要】

- 上司にとって最も安い「一目」は、**チーム全員の今日の記録 1 行ずつ**のフィード。取込一覧は本人分しか無い。
- **対策**: チーム画面に「今日の記録」フィード (担当・時刻・要約・案件へのリンク)。

### B3. 管理画面の数字が入力品質に引きずられる 【前提】

- A1 のゴミ案件は「進行中」の件数をそのまま水増しする。**B1 を作っても、A1 を直さなければ数字が信用されない。** 実行順序は A1/A2 → B1。

### B4. 上司向けの朝のブリーフが無い 【中】

- Morning Brief は担当者本人の「期限超過・今日やること・注意」のみ。上司には「昨日の記録件数 (担当者別)・新規案件・停滞が増えた案件・放置された確認」を送る版が要る。

### B5. 確認待ちを誰が放置しているか分からない 【中】

- チーム画面の「確認待ち N 件」は合計だけ。B1 の担当者別の表に「確認待ち」列を入れ、A7 のエスカレーションと合わせる。

## 4. うまく機能している点 (残すべきもの)

- 受注・失注・金額・顧客の確定は**必ず人が行う** (テストでも例外なく確認待ちになった)。
- 未確定の顧客に対する自動一致は `2627aaf` で止めた (2 件目以降も必ず聞く、確定したら聞かない)。
- プロンプトインジェクション (#30) は無視された。
- 取込の取り消し、監査ログ、担当者・顧客情報の編集、案件ごとの窓口、顧客ページ、検索、スヌーズ、戻るボタン。
- 同じメモの二重投稿は無視される (内容ハッシュ)。

| 優先 | 項目 | 内容 | 規模 |
|---|---|---|---|
| **P0** | A1 | 案件・顧客画面からの取り込み (案件に確定紐付け)。顧客名なしメモは「どの案件？」を 1 タップで聞き、該当なしは案件を作らずメモ保存。(顧客未特定) 案件の自動生成を廃止 | 中 |
| **P0** | A2 | 顧客の質問文を「メモを見せて 3 択」に変更。抽出された会社名の文らしさガード | 小〜中 |
| **P0** | A3 | 信頼度不足の次アクション提案を「AI の提案」として表示・1 タップ採用 | 小 |
| **P0** | A6 | 取り込みを受付即応答 (receive + 後処理) に変更 | 中 |
| **P0** | B1 | チーム画面に KPI タイルと担当者別の表 (A1 の後に) | 中 |
| P1 | A4 | 相対日付をコードで決定的に計算。質問は日付ボタンで | 小〜中 |
| P1 | A5 | 「無関係」判定を狭め、消さずにメモ保存。取り消し 1 タップ | 小 |
| P1 | A7 | 48 時間放置の確認を上司に表示・通知 | 小 |
| P1 | A8 | 案件の統合・アーカイブ、顧客の統合・改名 | 中 |

規模の目安: 小 = 半日〜1 日、中 = 2〜3 日 (Sonnet で 1 項目 = 1 コミットの進め方の場合)。

**推奨する順番**: A3 → A2 → A1 → A6 → B1 → (P1 群)。A3 と A2 は小さく効果が大きい。A1 はデータの根本。A6 は体感。B1 は A1 が終わってから作らないと数字が信用されない。
